# Does the lecture rely on anything the Bot-only platform drops?

Research for [#782](https://github.com/Daanish2003/bot-sdk/issues/782) (child of map [#781](https://github.com/Daanish2003/bot-sdk/issues/781)). Researched 2026-10-22 against `main` at a1e9441f.

## Question

Does any slide of the lecture rely on a feature #781 drops: MCP / connector tools, a user sending a Bot files or images, shared links, ratings, pin/archive, Projects, Artifacts, generated images, saved prompts, Instructions, `fetch_url`, past-chat search, compaction? For each hit: slide number, quote, and whether a Bot step already built it differently.

## Sources

- **Lecture write-up:** the first comment on [#383](https://github.com/Daanish2003/bot-sdk/issues/383) ("Lecture slides: How always-on agents work", 44 slides). Slide numbers below are its numbers.
- **Transcript:** `transcript-L1OBRtfPS34.pdf` (the talk's YouTube transcript), cited by timestamp.
- **Code:** `packages/bot-sdk/plugins/*` on `main`.
- **Earlier decisions:** [#573](https://github.com/Daanish2003/bot-sdk/issues/573) (the cheapest-first ladder) and [#417](https://github.com/Daanish2003/bot-sdk/issues/417) (step 6 map, its out-of-scope list).

## Answer

Two drops touch something the lecture calls for: **MCP/connector tools** and **image generation**. In both cases no Bot step has built the feature, and the assistant's version is not what a Bot would use. Dropping the assistant code takes nothing away from Bots. It does leave both as known gaps against the lecture. **Compaction** is also in the lecture, but the Bot already has its own version (step 8), which does not depend on the assistant's. Nothing in the lecture has a user hand a Bot a file. Every other drop is not in the lecture at all.

## Things to carry into the drop-list confirmation (#784)

1. **Connectors and image generation are lecture gaps, not keep reasons.** #781's keep rule ("keep only what Bots use today or the lecture calls for; nothing dropped is rebuilt as a Bot feature in this effort") lets the assistant versions go. Bots don't use them, and the lecture's versions would be new Bot work (connectors through the deferred-tool slot, each with its own auth). It is worth a line in the Bot-only ADR so the drop doesn't read as rejecting the lecture.
2. **User Attachments can go:** no slide has a user send a Bot a file. #781's condition for keeping them isn't met.
3. **Compaction drop is safe:** the Bot's Summary (slides 32–34) stands on its own.
