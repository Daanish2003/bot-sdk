# Prompt caching, compaction and tool search

Research for [#388](https://github.com/Daanish2003/ai-chat/issues/388) (child of map [#383](https://github.com/Daanish2003/ai-chat/issues/383), lecture slides 24 and 31–34). Researched 2026-10-16. Facts only, no recommendation.

## Question

What do the providers and our stack actually support for the lecture's context engineering?

- Prompt caching: TTLs and pricing for Anthropic (5 min and 1 h), OpenAI and Gemini. Explicit vs automatic caching, and prefix-match rules.
- Our stack: whether the TanStack AI adapters expose cache control and report cache-hit tokens, and what `@tanstack/ai-compaction` does.
- Tool search: provider tool-search tools vs a home-made names-first approach.
- Cache warming: whether it's possible, and what it costs.

Versions read: `@tanstack/ai` 0.66.0, `@tanstack/ai-anthropic` 0.20.0 (bundles `@anthropic-ai/sdk` 0.97.1), `@tanstack/ai-openai` 0.28.0 (with `@tanstack/openai-base`), `@tanstack/ai-gemini` 0.37.0, `@tanstack/ai-compaction` 0.1.14, all pinned in [`packages/chat-sdk/package.json`](../../../packages/chat-sdk/package.json) and read from the installed `node_modules/.pnpm` copies. Our curated defaults are `anthropic:claude-sonnet-5-5`, `openai:gpt-5.6` and `gemini:gemini-3.8-flash` ([`core/shared/chat/models.ts`](../../../packages/chat-sdk/core/shared/chat/models.ts) lines 218–220).

## Summary

- **All three providers cache by prefix.** A hit needs the request to start with exactly the same tokens as a recent one. Anthropic caches only where a breakpoint is marked (explicitly, or with one top-level `cache_control`). OpenAI and Gemini cache automatically. GPT-5.6+ also has an explicit mode, and Gemini 2.5 and 3.x have explicit `cachedContents` objects.
- **TTLs.** Anthropic: 5 minutes, or 1 hour, refreshed on every hit. OpenAI GPT-5.6+: at least 30 minutes. OpenAI earlier models: about 5–10 minutes in memory, or the `24h` option. Gemini implicit: not stated. Gemini explicit: 1 hour by default, any TTL you set.
- **Prices (multiples of the input price).** Anthropic: writes cost 1.25× (5 min) or 2× (1 h). Reads cost 0.1×, or 0.05× on Sonnet 5.5 and Opus 5.5. OpenAI GPT-5.6+: writes 1.25×, reads 0.1×. Older OpenAI models have no write charge. Gemini 3.8 Flash: reads are 10% of input, and explicit caches add $0.50 per 1M tokens per hour of storage.
- **Our stack caches nothing on Anthropic today.** The adapter can take `cache_control`, but we never pass it. OpenAI and Gemini cache implicitly with no code. The Anthropic, OpenAI and Gemini adapters all report cache-read tokens, and we store them as `cached`. The cost meter still prices every input token at the full input price.
- **Two things in our Run change the prompt prefix between calls.** The recalled Memories in the system prompt change with each user message. Once a Conversation is over budget, `evictOldest` moves the cut (and rewrites the marker text) on every model call.
- **`@tanstack/ai-compaction` is client-side middleware.** It has three strategies: drop the oldest messages, summarize them with your own call, or stub old tool results. We use `evictOldest` only. Anthropic also offers server-side compaction (on demand, in the background, or at a token threshold). Our installed SDK and adapter don't support the on-demand form.
- **Anthropic and OpenAI (GPT-5.4+) have native tool search with deferred tools.** Both keep the cached prefix intact. Gemini has none, and its docs say to keep 10–20 active tools. TanStack AI has its own names-first `lazy` tools, which add the discovered tools to the `tools` array. On Anthropic, any change to tool definitions invalidates the whole cache. The adapters pass neither provider's `defer_loading` nor `tool_search`.
- **Warming works on Anthropic** (`max_tokens: 0`, not streamed) **and on OpenAI GPT-5.6+** (`prompt_cache_options.prewarm`). Either way you pay a cache write and get no output. Gemini implicit caching has no warming call. Creating an explicit cache plays that role, at the cost of storage.

## 1. Prompt caching by provider

### Anthropic [A1]

| Fact               | Value                                                                                                                                                                                                                                                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| How it's turned on | Explicit `cache_control: { type: "ephemeral" }` on a block (up to 4 breakpoints per request), or **automatic caching**: one top-level `cache_control` that puts the breakpoint on the last cacheable block and moves it forward as the conversation grows (it uses one of the 4 slots). Without either, nothing is cached. |
| TTL                | 5 minutes by default; `"ttl": "1h"` for 1 hour. "Each cache hit or refresh renews it at no additional cost." The lifetime counts from the **start** of the request, so streaming time counts against it.                                                                                                                   |
| Write price        | 1.25× base input (5 min), 2× (1 h)                                                                                                                                                                                                                                                                                         |
| Read price         | 0.1× base input; **0.05× on Claude Opus 5.5 and Sonnet 5.5**; 0.025× on Fable 5.1 and Mythos 5.1. Breakpoints themselves cost nothing.                                                                                                                                                                                     |
| Minimum cacheable  | 512 tokens on Sonnet 5.5, Opus 5.5, Opus 5, Haiku 5.5 and others; 1,024–4,096 on older models. A shorter prompt is just not cached, with no error.                                                                                                                                                                         |
| Prefix order       | `tools` → `system` → `messages`. A change at one level invalidates that level and everything after it. Hits need a 100% identical prefix up to the breakpoint.                                                                                                                                                             |
| What invalidates   | Tool definitions (names, descriptions, parameters): all levels. Web search, citations, speed toggles: system and messages. `tool_choice`, images added or removed, thinking parameters, `output_config.effort`: messages.                                                                                                  |
| Lookback           | A write happens only at a breakpoint. A read walks back at most **20 blocks** from the breakpoint looking for an earlier write. A run of consecutive `tool_use` or `tool_result` blocks counts as one.                                                                                                                     |
| Usage fields       | `cache_creation_input_tokens` (split into `ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens`), `cache_read_input_tokens`, `input_tokens` (only the uncached tokens after the last breakpoint). Total input is the sum of all three.                                                                               |

### OpenAI [O1]

| Fact               | GPT-5.6 and later                                                                                                                                                                                                                                                                              | Earlier models (and GPT-5.5)                                                                                                                                                                                          |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| How it's turned on | On by default (implicit). Explicit mode: `prompt_cache_options.mode: "explicit"` plus `prompt_cache_breakpoint: { "mode": "explicit" }` on an input content block. Top-level `instructions` can't carry a breakpoint. Up to 4 cache writes per request, and the implicit breakpoint takes one. | Implicit only. Breakpoints every 2,048 tokens on GPT-5.5; model-dependent elsewhere.                                                                                                                                  |
| Minimum            | 1,024 visible input tokens                                                                                                                                                                                                                                                                     | Varies with tools, images, schemas, effort and verbosity                                                                                                                                                              |
| TTL                | `prompt_cache_options.ttl` accepts only `"30m"` (the default). A prefix stays eligible for at least 30 minutes after its latest write or reuse.                                                                                                                                                | `prompt_cache_retention: "in_memory"`: about 5–10 minutes after inactivity, up to 1 hour. `"24h"`: typically about 30 minutes, up to 24 hours. The default is `24h` without Zero Data Retention, `in_memory` with it. |
| Price              | Writes 1.25× uncached input. Reads 0.1× (0.05× on GPT-6.1 Sol)                                                                                                                                                                                                                                 | No write charge; reads discounted ("up to 95%")                                                                                                                                                                       |
| Routing            | `prompt_cache_key` is optional, mainly for separate cache accounting                                                                                                                                                                                                                           | `prompt_cache_key` routes related requests to the same cache; about 15 requests per minute per key                                                                                                                    |
| Prefix             | The whole rendered prefix up to a breakpoint must match; the longest match is used. Tools, `text.format` schemas, `reasoning.effort`, `text.verbosity` and `parallel_tool_calls` are all part of the prefix.                                                                                   | Same                                                                                                                                                                                                                  |
| Usage fields       | `usage.input_tokens_details.cached_tokens`, `usage.input_tokens_details.cache_write_tokens`                                                                                                                                                                                                    | `cached_tokens`, rounded down to a multiple of 128                                                                                                                                                                    |

The guide covers the Responses API (which our adapter uses) and the Agents API. It doesn't mention Chat Completions. Cached tokens still count toward tokens-per-minute limits.

## 2. Our stack

### What the adapters expose

| Provider  | Cache control in TanStack AI                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Cache tokens reported                                                                                                                                                                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Anthropic | **Yes.** `modelOptions.cache_control` (automatic caching) is on the adapter's allow-list (`adapters/text.ts` line 553). A breakpoint goes on one system prompt via the structured `systemPrompts: [{ content, metadata: { cache_control } }]` form (`text/text-provider-options.ts`), on message parts via part `metadata.cache_control` (`adapters/text.ts` lines 641, 757, 789), and on a custom tool via `metadata.cacheControl` (`tools/custom-tool.ts`).                                                     | `cache_read_input_tokens` becomes `promptTokensDetails.cachedTokens`, and `cache_creation_input_tokens` becomes `cacheWriteTokens` (`usage.ts`). `promptTokens` is Anthropic's `input_tokens`, so it excludes both.                                                            |
| OpenAI    | `modelOptions.prompt_cache_key` and `prompt_cache_retention: 'in-memory' \| '24h'` are typed (`text/text-provider-options.ts` lines 91–99). `prompt_cache_options` (GPT-5.6 mode, TTL, prewarm) and `prompt_cache_breakpoint` aren't typed anywhere in the package. The Responses adapter spreads `modelOptions` into the request (`openai-base/src/adapters/responses-text.ts` line 2219). System prompts are joined into top-level `instructions` (line 2225), where an explicit breakpoint isn't allowed [O1]. | Responses: `input_tokens_details.cached_tokens` becomes `promptTokensDetails.cachedTokens` (`openai-base/src/usage.ts` line 111). The Responses builder does **not** read `cache_write_tokens`. The Chat Completions builder reads it only from Moonshot's non-standard field. |
| Gemini    | `modelOptions.cachedContent: \`cachedContents/${string}\`` is typed (`text/text-provider-options.ts` line 177). Nothing in the package creates a cache. Implicit caching needs no option.                                                                                                                                                                                                                                                                                                                         | `usageMetadata.cachedContentTokenCount` becomes `cachedTokens` (`usage.ts` line 138)                                                                                                                                                                                           |

`@tanstack/ai` emits these as OpenTelemetry `gen_ai.usage.cache_read.input_tokens` and `gen_ai.usage.cache_creation.input_tokens` (`src/middlewares/usage-attributes.ts`).

### What our code does with them

- **We send no cache control.** `cache_control`, `prompt_cache` and `cachedContent` appear nowhere in `packages/chat-sdk/core`. `run-plan.ts` passes `systemPrompts` as plain strings (line 274). `generationOptionsFor` builds `modelOptions` from max output and effort only (line 293). So Anthropic Runs are not cached, and OpenAI and Gemini Runs get only implicit caching.
- **Cached tokens are stored but not priced.** `normalizeUsage` ([`core/server/chat/usage.ts`](../../../packages/chat-sdk/core/server/chat/usage.ts)) adds cache reads and writes back into `input` for `anthropic` and `bedrock`, whose input excludes them, and keeps `cached` as its own field. `modelCostMicros` ([`core/server/chat/meter.ts`](../../../packages/chat-sdk/core/server/chat/meter.ts) line 122) prices `usage.input` at `inputUsdPerMillion` with no cache discount or write premium, unless the provider reported a cost.
- **The system prompt changes from one message to the next.** `systemPromptsFor` ([`core/server/chat/system-prompts.ts`](../../../packages/chat-sdk/core/server/chat/system-prompts.ts)) orders the prompts as citation, Knowledge file names, the user's Instructions, the Project's Instructions, then the Memories recalled for this Run. `run-plan.ts` recalls the Memories from the latest user text (`recalledMemoriesPrompt({ latestText })`). The Artifact context prompts come after them. On Anthropic, a change in `system` invalidates `system` and `messages` [A1]. On OpenAI and Gemini, everything after the first differing token misses.

### `@tanstack/ai-compaction` [T1]

- It is a `chat()` middleware (`withCompaction`). It runs in `onConfig` before **every model call**, except the `init` phase. It rewrites only `providerMessages`, the copy sent to the provider. "The canonical transcript and system prompt stay unchanged."
- It triggers when the estimated tokens (chars ÷ 4 by default) exceed `maxTokens`. The strategies:
  - `evictOldest({ keepRecentTokens, marker })`: drops the head and prepends a user message `[N earlier message(s) omitted to save context.]`. No model call.
  - `summarizeOldest({ summarize, keepRecentTokens, summaryRole })`: replaces the head with your own summary, wrapped in `<untrusted-conversation-summary>`. One model call, which you supply.
  - `clearToolResults({ keepRecentToolResults = 3, stub })`: stubs old tool output and keeps every message in place.
  - `composeStrategies(...)`: runs them in order and stops once under budget.
- The cut never splits a tool call from its results (`splitAtRecent`).
- With `withPersistence` metadata, it saves a checkpoint (hash of the source messages plus the compacted messages), and the next request reuses the compacted prefix. Without metadata it is stateless. We don't use `withPersistence` anywhere in `packages/`.
- **Our use.** [`core/server/chat/compaction.ts`](../../../packages/chat-sdk/core/server/chat/compaction.ts) runs `evictOldest({ keepRecentTokens: budget })` with `maxTokens: budget`. The budget is the window less max output less 2,000 tokens. Images and PDFs count as 1,600 tokens each. Once over budget, each model call keeps the newest messages that fit the whole budget. So the cut moves forward as messages are added, and the marker's count changes. The messages part of the prefix is therefore different on every call after the first eviction.
- It does nothing like the lecture's "summarize while away" (slide 34). It runs only inside a model call, and it has no timer or idle trigger.

### Anthropic server-side compaction [A2, A3]

- **Three kinds.** On demand: you send `compaction: { type: "summarize" }`, beta `compact-2026-09-04`, and get back one signed `compaction` block. At a token threshold: the context-management edit `compact_20260112`. In the background: the on-demand request runs while the conversation carries on, and you swap the block in when it arrives.
- **On demand.** Supported on Sonnet 5.5, Opus 5.5, Haiku 5.5 and others. Send the same `system` and `tools` as the conversation. The block goes first in `messages` from then on. `cache_control` on the block puts a breakpoint after the summary. Optional `instructions` (up to 16,384 characters) replace the default prompt. The call is billed like any request and reported in `usage.iterations`.
- **Keeping recent turns.** "Compaction that keeps recent turns" keeps the last turns word for word, as slide 34's "last few messages kept word for word" does.
- **Our installed packages.** `@anthropic-ai/sdk` 0.97.1 has no `compact-2026-09-04` beta. `BetaContextManagementConfig.edits` does include `BetaCompact20260112Edit`, `BetaClearToolUses20250919Edit` and `BetaClearThinking20251015Edit`. The TanStack adapter forwards `modelOptions.context_management` and adds the `context-management-2025-06-27` beta (`adapters/text.ts` lines 182–213). It has no `compaction` key on its allow-list. Its only handling of compaction is mapping `stop_reason: 'compaction'` to a plain `RUN_FINISHED` (line 1633).

## 3. Tool search

| Option                            | How it works                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Cache effect                                                                                                                                                                                                                                  | Available to us                                                                                                                                                                                                                                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Anthropic tool search** [A4]    | Add `tool_search_tool_regex_20251119` or `tool_search_tool_bm25_20251119`, and send **every** tool on every request, deferred ones with `defer_loading: true` (at least one must stay non-deferred; up to 10,000 deferred). A search returns 5 `tool_reference` blocks by default, which the API expands. Custom search: return `tool_reference` blocks from your own tool. Supported on Sonnet 5.5, Opus 5.5, Haiku 5.5 and others. Not metered separately. | "The API excludes deferred tools from the system-prompt prefix… The prefix is untouched, so prompt caching is preserved." A deferred tool can't carry `cache_control`.                                                                        | The SDK 0.97.1 types have `defer_loading` and both tool-search types. The TanStack adapter has no tool-search provider tool (`tools/anthropic-provider-tool.ts` lists bash, code_execution, computer_use, memory, text_editor, web_fetch, web_search). `convertCustomToolToAdapterFormat` drops `defer_loading`. |
| **OpenAI tool search** [O2]       | `{ "type": "tool_search" }` plus `defer_loading: true` on functions, namespaces or an MCP server; gpt-5.4 and later. Hosted (OpenAI searches) or `execution: "client"` (you return a `tool_search_output` with the tools to load). They recommend fewer than 10 functions per namespace.                                                                                                                                                                     | "Discovered tools are injected at the end of the context window… which preserves the model's cache", but "changing the loaded tool set will break the model's cache from that point forward."                                                 | `tool_search` and `defer_loading` appear nowhere in `@tanstack/ai-openai` 0.28.0 `src`.                                                                                                                                                                                                                          |
| **Gemini** [G4]                   | No tool search or deferred loading documented. Best practice: "Keep active set to 10-20 tools maximum." `tool_choice` `allowed_tools` restricts which declared tools the model may call.                                                                                                                                                                                                                                                                     | Not applicable                                                                                                                                                                                                                                | Not applicable                                                                                                                                                                                                                                                                                                   |
| **TanStack AI `lazy` tools** [T2] | Names first: a tool defined with `lazy: true` isn't sent. A synthetic `__lazy__tool__discovery__` tool lists the lazy tool names (optionally with the first sentence or the full description), and calling it returns their schemas. `getActiveTools()` then sends eager + discovered + the discovery tool, dropping it once all are discovered. Past discoveries are rebuilt from message history.                                                          | Each discovery **adds definitions to `tools`**, and the last one removes the discovery tool. On Anthropic, a tool-definition change invalidates `tools`, `system` and `messages` [A1]. On OpenAI, the prefix changes from the `tools` onward. | Built into `@tanstack/ai` 0.66.0 (`activities/chat/tools/lazy-tool-manager.ts`); works on every adapter. We don't use it (`lazy` appears nowhere in `packages/chat-sdk/core`).                                                                                                                                   |

Anthropic's docs give the case for tool search: about 55k tokens of definitions for a five-server MCP setup, reduced "by over 85 percent". Tool-selection accuracy "degrades once you exceed 30–50 available tools". Tool search is for "10 or more tools" or more than 10k tokens of definitions [A4].

## 4. Cache warming

| Provider              | Mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                              | Cost                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Anthropic [A1]        | A request with `max_tokens: 0`, the breakpoint on the shared prefix and a placeholder user message. It returns empty `content`, `stop_reason: "max_tokens"` and `usage`. It must use the same thinking and effort settings as the real call. It's rejected with `stream: true`, extended thinking, `output_config.format`, `tool_choice` `any` or `tool`, and in Batches. For parallel requests, the entry exists only once the first response begins. | A cache write (1.25× or 2× the prefix); zero output tokens. Keeping a 5-minute entry warm means re-sending at least every 5 minutes, or using the 1-hour TTL. |
| OpenAI GPT-5.6+ [O1]  | `prompt_cache_options.prewarm: true` on a Responses request with the shared prefix; "prepares the cache without generating output". The page doesn't say what it returns.                                                                                                                                                                                                                                                                              | Billed at the cache-write rate (1.25×)                                                                                                                        |
| OpenAI earlier models | No warming call documented                                                                                                                                                                                                                                                                                                                                                                                                                             | Not applicable                                                                                                                                                |
| Gemini [G2]           | No warming call for implicit caching. Creating an explicit `cachedContents` object (2.5 and 3.x) puts the prefix in the cache ahead of the request.                                                                                                                                                                                                                                                                                                    | Storage per token-hour for the TTL (above); the cached tokens are billed at the caching rate when used                                                        |

**Arithmetic from the multipliers above (not a provider statement).** Take a prefix of P tokens. On Sonnet 5.5, warming then hitting costs 1.25P + 0.05P = 1.30P in input-price units. Not warming costs 1.25P, since the first real call writes the entry. So a warm that's used adds 0.05P. A warm that's never used wastes 1.25P (2P on the 1-hour TTL). On GPT-5.6 the same sums are 1.35P vs 1.25P.

**The lecture's timing against the TTLs.** Slide 34 writes the summary "about 10 minutes" after a big turn, "while the provider's cache is still warm". That holds for OpenAI GPT-5.6+ (at least 30 minutes), for OpenAI `24h` retention, for Gemini explicit caches (1 hour by default), and for Anthropic only with the 1-hour TTL. The 5-minute Anthropic entry, and OpenAI's older `in_memory` retention (about 5–10 minutes), may have expired by then.

**Wiring warming through our adapter.** The TanStack Anthropic adapter streams by default (`mapCommonOptionsToAnthropic(options, { stream = true })`). A `max_tokens: 0` warm would therefore have to go through the adapter's non-streaming path or a direct SDK call. Whether TanStack's non-streaming path sends `max_tokens: 0` was not traced.

## Not covered

- Whether TanStack's tool list is ordered the same on every call (slide 33's "built in a fixed order and sorted") was not traced through `chat()`.
- The Gemini adapter's handling of `cachedContent` together with `systemInstruction` and `tools` on the same request: the Gemini docs don't say whether a request that names a cache may also set them.
- Bedrock (`cacheApartProviders`) and OpenRouter cache behaviour.
- Anthropic threshold-compaction (`compact_20260112`) defaults and how it interacts with our stored Message parts.
