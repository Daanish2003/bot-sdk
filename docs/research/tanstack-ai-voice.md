# TanStack AI voice and the Web Speech API

Research for issue #234 (child of the map #229, "Wayfinder: Chat extras"). Researched on 2026-10-12 against the packages installed in `packages/chat-sdk/package.json`: `@tanstack/ai` 0.66.0 (with `@tanstack/ai-event-client` 0.13.1), `ai-openai` 0.28.0, `ai-gemini` 0.37.0, `ai-groq` 0.8.5, `ai-grok` 0.21.2, `ai-mistral` 0.6.15, `ai-openrouter` 0.21.2, `ai-cloudflare` 0.2.5, `ai-byteplus` 0.6.2, `ai-lovable` 0.5.2, `ai-anthropic` 0.20.0, `ai-bedrock` 0.4.5, `ai-ollama` 0.11.14, `ai-llmgateway` 0.2.5, `ai-vercel-gateway` 0.3.7, `ai-react` 0.30.1.

How to read the sources:

- **Package sources.** Paths are relative to `node_modules/@tanstack/<package>/src/`.
- **External sources.** Vendor pricing and docs pages, MDN, MDN browser-compat-data (`api/SpeechRecognition.json`, fetched 2026-10-12), caniuse, the WebKit blog and the Web Speech API on-device explainer. Each claim names its source.
- **Unverified.** Nothing here was run against a live Provider or browser. Claims that rest on memory or a secondary source are marked **unverified**.

## Recommendation

1. **The provisional split holds, with two corrections.**
   - **Read-aloud (`speechSynthesis`) by default is sound.** It works in every major browser, is free and needs no Quota. Some voices are remote (`localService === false`); prefer local voices.
   - **Dictation (`SpeechRecognition`) by default is weaker than "free and private".** Chrome and Edge send the audio to the browser vendor's server unless the page asks for on-device recognition (`processLocally = true`, Chrome 139+, 17 locales, a language-pack download). Firefox has no `SpeechRecognition` in release builds, and Safari needs Siri turned on. So the browser default is free and Quota-free, but not offline, not private by default, and absent in Firefox.
2. **Provider voice is only possible on 7 of the 15 installed adapters.** Transcription: OpenAI, Groq, Grok (xAI), Cloudflare, BytePlus, Lovable. Speech: OpenAI, Gemini, Groq, Grok, Cloudflare, BytePlus, Lovable. Anthropic, Mistral, OpenRouter, Bedrock, Ollama, LLM Gateway and Vercel AI Gateway have neither. A user whose only Provider credentials are for, say, Anthropic or OpenRouter gets no Provider voice.
3. **Meter in our own code; don't trust `usage` alone.**
   - **Transcription.** OpenAI, Grok and BytePlus put a `usage` on the result (seconds, or tokens for `gpt-4o-*-transcribe`). Groq and Cloudflare return only `duration`.
   - **Speech.** Only Gemini returns `usage` (tokens). OpenAI, Groq and Grok return none, so price speech from the input text length, which is how they bill.
   - **Cost.** No voice adapter fills `usage.cost`; price from our own table.
4. **There is no audio streaming through `generateSpeech`/`generateTranscription`.** `stream: true` wraps the one finished result in `RUN_STARTED` / `CUSTOM generation:result` / `RUN_FINISHED`. Live dictation through a Provider would need the realtime adapters (`useRealtimeChat`, OpenAI/Gemini/Grok `realtime/`), which this research did not cover.
5. **`@tanstack/ai-react` already ships the client parts**: `useAudioRecorder` (getUserMedia + MediaRecorder, gives `.base64` for the generation hooks), `useTranscription` and `useGenerateSpeech`. No new dependency is needed for Provider voice.

## 1. The core API (`@tanstack/ai` 0.66.0)

Source: `ai/src/activities/generateSpeech/`, `ai/src/activities/generateTranscription/`, `ai/src/types.ts`, `ai/src/activities/stream-generation-result.ts`.

|              | `generateTranscription`                                                                                                                              | `generateSpeech`                                                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Adapter kind | `'transcription'`, method `transcribe()`                                                                                                             | `'tts'`, method `generateSpeech()`, optional `listVoices()`                                                                                                    |
| Input        | `audio: string \| File \| Blob \| ArrayBuffer` (string = base64 or data URL), `language?` (ISO-639-1), `prompt?`, `responseFormat?`, `modelOptions?` | `text` or `turns` (multi-voice dialogue), `voice?`, `format?: 'mp3'\|'opus'\|'aac'\|'flac'\|'wav'\|'pcm'`, `speed?` (0.25–4.0), `timestamps?`, `modelOptions?` |
| Output       | `{ id, model, text, language?, duration?, segments?, words?, usage?, artifacts? }`                                                                   | `{ id, model, audio (base64), format, contentType?, duration?, alignment?, segments?, usage?, artifacts? }`                                                    |
| Streaming    | `stream: true` only wraps the one-shot result as AG-UI chunks                                                                                        | same                                                                                                                                                           |
| Capabilities | none declared                                                                                                                                        | `capabilities.maxSpeakers` and `capabilities.timestamps`; the activity rejects `turns` or `timestamps` the adapter didn't declare                              |
| Events       | —                                                                                                                                                    | `speech:request:started/completed/error`, `speech:usage`; middleware `onUsage` runs when `result.usage` is set                                                 |

`usage` is the shared `TokenUsage` (`ai-event-client/src/index.ts`): token fields, plus `billed?: { quantity, unit }` where `unit` is `'seconds' | 'characters' | 'tokens' | …`, plus `cost?` / `costDetails?` (Provider-reported money, filled by no voice adapter).

|                                      | Units we know after the call      | Bills on                      |

For a Quota check _before_ the call: transcription cost is knowable from the recording length (the client has it), and speech cost from the reply's character count.

## 4. The browser's Web Speech API

### `SpeechRecognition` (dictation)

| Browser                      | Support                                                                                                                                      | Source                                                                                |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Chrome (desktop and Android) | `webkitSpeechRecognition` since 33; unprefixed and `processLocally`, `available()`, `install()` since 139 (on-device statics not on Android) | MDN browser-compat-data                                                               |
| Edge                         | BCD mirrors Chrome; caniuse marks it unsupported. **Unverified** which is right in practice                                                  | BCD, [caniuse](https://caniuse.com/speech-recognition)                                |
| Safari (macOS, iOS)          | `webkitSpeechRecognition` since 14.1; no `processLocally`. Uses "the same speech engine as Siri" and needs Siri turned on; 50+ languages     | BCD, [WebKit blog](https://webkit.org/blog/11648/new-webkit-features-in-safari-14-1/) |
| Firefox                      | preview / disabled by default; not in release                                                                                                | BCD, caniuse                                                                          |

**Where the audio goes.** "On some browsers, like Chrome, using Speech Recognition on a web page involves a server-based recognition engine. Your audio is sent to a web service for recognition processing, so it won't work offline." ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)). When `processLocally` is false (the default) "any available recognition method (cloud-based or on-device) may be used"; when true "neither raw audio nor transcriptions leave the user's device" ([on-device explainer](https://github.com/WebAudio/web-speech-api/blob/main/explainers/on-device-speech-recognition.md)). Chrome's on-device locales listed there: de-DE, en-US, es-ES, fr-FR, hi-IN, id-ID, it-IT, ja-JP, ko-KR, pl-PL, pt-BR, ru-RU, th-TH, tr-TR, vi-VN, zh-CN, zh-TW. `available()` returns `unavailable | downloadable | downloading | available`; `install()` downloads the pack and may prompt. Safari's server/on-device split is not documented (**unverified**).

Other limits: `lang` defaults to the page or user-agent language; the spec is a Community Group draft, not a standard ("not Baseline", MDN). Quality varies by browser and language (**unverified**; no primary benchmark found).

### `speechSynthesis` (read-aloud)

Supported in Chrome 33+, Edge 14+, Safari 7+ (iOS 7+), Firefox 49+, Chrome and Firefox for Android ([caniuse](https://caniuse.com/speech-synthesis), ~96% global). Voices come from the OS and browser; `SpeechSynthesisVoice.localService` "indicat[es] whether the voice is supplied by a local speech synthesizer service (`true`), or a remote speech synthesizer service (`false`)" ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)). So a remote voice sends the reply text to a vendor; filter on `localService` to keep it on the device. That Chrome's "Google …" voices are the remote ones is **unverified**.
