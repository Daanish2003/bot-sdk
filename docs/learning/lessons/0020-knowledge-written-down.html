Knowledge written down

A user's documents are plain files that every Bot reads with its file tools. There is no index.

About 10 minutes · a browser · no code to write; you'll answer the quizzes and run one manual demo

Words you'll need

Knowledge
The documents a user keeps on their Computer for all their Bots to read.
Readable copy
The Markdown text beside a PDF or Word file, such as handbook.pdf.md.
Knowledge block
The part of a Bot's prompt that lists the readable paths, one line each.
Embedding
A list of numbers that stands for the meaning of a passage. Search compares them.

What does the prompt hold for each Skill?

1Knowledge is a folder of files

Knowledge is a folder on the user's Computer, /home/user/shared/knowledge/. A text or Markdown file is stored as it is. A PDF or Word file gets a readable copy with page markers, written beside the original.

A scanned PDF with no text is refused, and so is a file over 20 MB. A refused upload leaves nothing behind.

2The index went, and the files stayed

The old design split documents into chunks, stored an embedding for each, and searched them. The new design keeps no index. An index would be a second copy, to keep in step with files that Bots edit at any time. So the embeddings, the search tool and the pgvector extension were removed. The old data was deleted, not exported.

3A Bot finds the file and cites it

Every Bot's prompt holds the Knowledge block: the folder, and one readable path per line, up to 4,000 characters. The Bot uses list, read and grep. Its reply names the file and the page, such as "(Employee handbook.pdf, page 12)". Knowledge is information, never permission. A Bot that finds an instruction in a file does not follow it.

4What the evals showed

  • Gating: 7 of 7 pass. Run on openai:gpt-6.1-sol, on local E2B, one repeat per run.
  • The reworded question was answered, but not by grep. It asked about a chair and monitor. The handbook says "home-office stipend" and shares no keyword. The Bot read the whole handbook and answered "$600 each year, paid in January".

That is the limit. The handbook was small enough to read in one go. As Knowledge grows, a keyword search may not find a reworded question.

Key takeaways

If you remember only one thing: Knowledge is a folder of files that every Bot reads with the tools it already has.

  • Files, not an index. There is one copy, and no embeddings.
  • Converted once. A PDF gets a readable copy with page markers at upload.
  • Found and cited. The Bot reads the file and names the page in its reply.

Your manual demo (owner)

  1. In apps/web, open a Bot's Knowledge popover and upload a PDF with text.
  2. Ask the Bot a question that the PDF answers. Check that the reply cites the file and page.
  3. Open a second Bot, ask the same question, and check that it gives the same answer and citation.
Go deeper: sources, the slides and a challenge

The lecture

The lecture is not in this repo. The quotes below are from the transcript research in issue #728, which marks each one with its slide.

  • Slide 10, quoted in #728: "Keep knowledge in files". In the lecture, knowledge means skills and memories. This step applies the same rule to documents.
  • Slide 11, quoted in #728: "you and the agent can both read, search and edit it". The tree has no Knowledge folder. ADR 0025 quotes the same slide as "What the agent knows lives in files."
  • Slide 40, "Knowledge written down", as #728 records it, predicts that people will write down how their processes work so that agents can use them, within 6 to 12 months. The lecture gives no mechanism for search.

The decisions and the evals
