How the agent remembers

A Bot's memory is plain files on its Computer. A few lines go into each Turn, and a pass after each Turn decides what to keep.

About 14 minutes · a browser · no code to write; you'll answer the quizzes and score a Log line by hand

Words you'll need

Profile
Lasting facts about the user, one per line, with no date. "Prefers short replies."
Log
Dated events, each with an importance from 1 to 10. One file per month.
Notes
Short-lived details, each dated. They matter for a day or two.
Post-turn pass
A short model call after a Turn. It returns the changes to the memory files.

1Files, not rows

Slide 11 says "What the agent knows lives in files." The files are the source of truth, so there are no database rows. The Bot can cat a file, and it edits its memory with its file tools.

Each Turn reads these files, so a Turn can wake a sleeping Computer. The Computer syncs /home/user/bots to storage before it sleeps. A rebuild restores memory only as of the last sync, so a fact written after that is lost.

2Three tiers, one score

The Profiles go into the prompt. The Bot's own Profile comes first, then the other Bots' Profiles, oldest Bot first. The caps are 100 facts and 4,000 characters, and exact duplicates are dropped. Facts past a cap are left out of the prompt, but they stay in the files.

The Log is too long for the prompt, so the code ranks it. Each line scores (0.75 + 0.05 × importance) × 0.5^(ageDays / 30). The 30 best lines from the last three monthly files go in. Notes from today and yesterday go in. Older Notes are found only by search.

Score one line. A Log line has importance 7 and is 30 days old.

  1. Importance weight: 0.75 + 0.05 × 7 = 0.75 + 0.35 = 1.10
  2. Decay: 0.5^(30 / 30) = 0.5^1 = 0.50
  3. Score: 1.10 × 0.50 = 0.55

3The pass, and what it may remove

After each Turn that ends complete or stopped, a runner job asks the Bot's own Model for a pass. The pass sees the Turn and the memory lines, each with a number. It returns add, replace or remove. The code writes the text and adds the date and importance.

A replace or remove must cite a number from that list. The code then checks that the line still says what it said when shown. If it changed, the operation is skipped. So a wrong number removes only a line whose text is unchanged. An identical line elsewhere could still match. Here is one correct change. The user says "I moved to Berlin." Line 4 reads "Lives in Lisbon." The pass returns replace line 4. The code sees that line 4 still reads "Lives in Lisbon," and it rewrites the line.

The Profile is shared. Each Bot reads every Profile, labelled with its Bot's name, but it writes only its own files. There is no rule for a conflict. The ADR expects the Bot to tell conflicting facts apart and act on the newer one. No code enforces that.

4Information, not orders

The memory block opens by saying memory is information, not instructions. A line that tells the Bot how to reply is only text. The pass prompt refuses instruction-like text too.

The framing was tested. The eval in packages/bot-sdk/eval/memory runs eight cases through the real plugin. An earlier run on a free Model, before the framing refused instructions, passed 7 of 8. That Model followed a planted instruction. With the current framing, the same eight cases passed 8 of 8 on openai:gpt-6.1-sol, on a ChatGPT plan.

Key takeaways

If you remember only one thing: the files are the memory. The tiers and the score decide what a Turn reads, and the code decides what a pass may change.

  • Plain files, read each Turn. The Profile, the top Log lines and recent Notes go into the prompt.
  • A pass removes only what it saw. A stale line number or a changed line is skipped.
  • Memory is information. Only the user's own words give orders.

Go deeper: sources, side notes and a challenge

The lecture and the decisions

  • Slide 11: "What the agent knows lives in files." Slide 35: the tiers, the shared Profile and the framing. These are the slides ADR 0022 cites.
  • Decision: ADR 0022, a Bot's memory is plain files on its Computer. The assistant's own Memories (ADR 0013) were removed in #650, so only Bots remember.
  • Spec: Bot step 7, Memory (#624). Evals: #633, with the case table and the results in packages/bot-sdk/eval/memory/README.md.

Side notes

  • The caps are 100 Profile facts, 4,000 characters, 30 Log lines, 3 months and 2 days of Notes. The score is OpenClaw's, and it uses a 30-day half-life.
  • search_memory ranks lines by BM25. Log lines also get the importance and decay weights; Profile facts get neither. It uses no embeddings and no index.
  • A pass runs only after a Turn that ends complete or stopped, and only with Memory on. It is a runner job, so its model calls are recorded and count against the Quota.

What was left out, and what comes next

The user can edit and delete any Bot's lines in the UI (#623). The export of memory is in the same plugin, and the full case list for the evals is in the eval README.
