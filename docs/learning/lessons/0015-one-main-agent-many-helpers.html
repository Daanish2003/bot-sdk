ai-chat architecture · Lesson 15

One main agent, many Helpers

A Turn stops after 10 Steps or 5 minutes. For bigger work the Bot hands a task to a Helper, keeps talking, and hears back as a Trigger.

About 14 minutes · a browser · no code to write; you'll answer the quizzes and follow a Helper's states

Words you'll need

Helper
An agent a Bot hands one complete task to. It works in its own fresh context and reports back briefly.
Screen
One display on the Computer, with its own Chrome. A Computer-use Helper works on it.
To-do list
The Bot's Helpers that are still working or waiting for the user.
Computer card
A Message part where a Helper hands its Screen to you, for a login or a captcha.

Warm-up · Lesson 14

What does a Check-in do when its time comes?

  1. It hands the Router a Trigger with source check_in
  2. It waits for the user's Approval
  3. It repeats on a schedule

1Hand off, then keep talking

Slide 27 says the main agent "answers quick questions itself" and "hands bigger tasks to a helper, so it can keep talking to you." Slide 26 adds that a separate helper does the clicking, so screenshots don't fill the main agent's context. This step builds two kinds: a General Helper (shell, files, web search) and a Computer-use Helper (a Screen's browser and desktop).

start_helper saves a running row in chat.bot_helper and queues a bot.helper job. The Turn carries on. The Helper sees only its task, so the task must stand alone. A Bot may have three General Helpers and one Computer-use Helper at once. A Helper is its own job, not a child of the Turn (the ADR 0011 amendment), so Stop on the Turn ends the Turn only.

2The report is a Trigger

A Helper runs the Turn's loop for at most 50 Steps and 30 minutes. Its last Step's text is its report, cut to 2,000 characters. Its last Checkpoint hands the Router a Trigger with source helper and the ID helper:<id>:<n>. A Helper that runs out or crashes still ends error and still reports.

The to-do list has no table. It is the Bot's running and waiting Helpers, listed in each Turn's input after the time notice, one line each, and never in the system prompt. The Bot can check_helper, message_helper and stop_helpers.

3Screens, and handing one to you

A Computer-use Helper takes the lowest free Screen, 1 to 4, across all the user's Bots. It reads pages with the Browser tools and uses desktop for the rest. Each Bot's Chrome profile stays on the Computer, so a rebuild loses sign-ins.

At a login, code, captcha or payment it calls ask_user. Its transcript is saved, its status becomes waiting, a Computer card Message is written, and the job ends, with no timeout. The card opens a live view, view-only until Take control. What you type never reaches the Model. Done flips the card to done and starts a fresh job that answers the call. The Host mounts bot.screenHandler for the page and bot.screenSocket for the socket.

4The cheapest way first, and a gap

The Bot's prompt says: try what it knows or has in its files, then web_search, then a Helper. Connectors are not on the ladder.

The gap: Anthropic and OpenAI each ship a computer toolset, but the pinned TanStack AI adapters don't support either (#562). So desktop is a plain tool over xdotool on a 1280×800 screen that returns screenshots as image parts. Only the newest 3 stay in the Helper's input.

Key takeaways

If you remember only one thing: a Helper is its own job. The Bot hands off and keeps talking, and the report comes back as a Trigger.

  • The to-do list is the live Helpers. It has no table, and the Bot sees it in each Turn's input.
  • A hand-off ends the job. The row says waiting until you tap Done, and a new job carries on.
  • Cheapest first. Knowledge and files, then web search, then a Helper.

Go deeper: sources, side notes and a challenge

The lecture and the decisions

  • Slide 26: "A separate helper agent does the clicking, so screenshots don't fill up the main agent's context." Slide 27: the main agent hands "a complete task description" to helpers and gets "a short report". It also lists a to-do list, checking on a helper, sending it a message and stopping all helpers. Slide 20's "Helper finished" is the report. The lecture's Video helper and Cloud coding agent have no build step yet.
  • Spec: Bot step 6, Helpers (#587). Map: #417.
  • Decisions: the Helper job (#565), the to-do list (#567), the hand-off (#568), the ladder (#573) and the adapters' computer toolsets (#562).

Side notes

  • Billing: each Helper model call records usage of kind helper, against the same Quota. The Quota is checked when a Helper starts, so a resumed one is never refused.
  • Sleep: a running Helper keeps the Computer awake through a busy check (hasRunningHelper); a waiting one does not.
  • If the Computer was rebuilt while the Helper waited, the answer to ask_user adds that the browser restarted and sign-ins were lost.
  • Done on a Helper that was stopped is refused: "This task was stopped." A stopped waiting Helper's card reads cancelled.
  • The example Host mounts the page handler in a Next route. A Next route can't upgrade a WebSocket, so the live view's socket needs a WebSocket-capable server; its README says so, and apps/web shows how.
  • Tests live beside the others in packages/bot-sdk/test. Evals: eval/turn for the ladder and eval/computer for the Screens.
