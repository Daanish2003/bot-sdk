Testing seams

Swap the outside world for fakes at one place: AppDeps.

About 14 minutes · a browser · you'll write round(...parts) and testKind(path)

Words you'll need

Seam
A place where a test can put a fake in place of a real part, without editing the code under test.
Fake
A small working stand-in for a real service, such as an adapter that plays a script instead of calling a Provider.
Unit test
A test of pure code with no database. Its file ends in .test.ts.
Integration test
A test against a real Postgres test database. Its file ends in .integration.test.ts.

1AppDeps is the seam

Think of a power socket. handleChat, startRun and every router take deps and never build their own database or adapter, so a test can plug in a different object. Production gets createAppDeps (Lesson 1). Tests get createTestDeps.

Look at the right column. The database is still real Postgres, but adapterFor and fetch throw if a test forgets to script them, so no test can reach the network by mistake. The limits are tiny (20 ms snapshots, a 2 s cap), so a "timed out" test runs fast.

2The fake adapter plays a script

A real adapter streams chunks from a Provider. createFakeAdapter({ rounds }) streams chunks from a script you write with round, text, thinking, toolCall and runError. Each call to the adapter plays the next round, so a tool loop is two rounds.

With manual: true, every chunk waits until the test calls release(n). This is how a test looks at the database in the middle of a run. From handle-chat.integration.test.ts:

  1. send(): the reply row is streaming with no parts.
  2. fake.release(3): RUN_STARTED, TEXT_MESSAGE_START and the delta "Hello" go through.
  3. Poll the row until its parts are [{ text: "Hello" }]: a snapshot was written mid-run.
Quiz

A new integration test calls handleChat with plain createTestDeps(). What happens when the run needs an adapter?

  1. It calls the real Provider.
  2. It plays an empty script.
  3. It streams a canned reply.
  4. It throws "No fake adapter".

3Two kinds of tests

vitest.config.ts splits the files into two projects by name. Integration tests share one database, so they run one file at a time. The global setup applies every migration once, and setup.ts truncates every table before each test, so no test sees another's rows.

4Add a test for your change

Follow the picture from the top. If the change is pure logic (a branchFrom rule, a redaction), write a unit test next to the file. If it touches a table, a run or a router, write an integration test with the helpers: insertUser, insertConversation, createTestDeps({ adapterFor: () => fake.adapter }), then call handleChat or createTestClient({ user }), which calls appRouter in the same process.

Before you trust a new test, break the code and see it go red (AGENTS.md, section 5).

Key takeaways

If you remember only one thing: code takes deps in, so a test swaps in createTestDeps with a scripted fake adapter and a real test database.

  • One seam. AppDeps holds the database, adapterFor, searchClient, runs, limits and fetch. Test deps throw on the network.
  • Scripts, not Providers. round(text("Hello")) is one model call; manual: true with release(n) pauses a run mid-stream.
  • Two kinds. *.test.ts for pure code; *.integration.test.ts for anything that touches Postgres.

Go deeper: sources, side notes and a challenge

Where the fake comes from

fake-adapter.ts says it is "modelled on TanStack AI's in-repo createMockAdapter". It implements the same chatStream the real adapters have, so chat() can't tell the difference.

Numbers today

The repo has 29 unit test files and 14 integration test files. CI sets TEST_DATABASE_URL in .github/workflows/ci.yml; locally the default is postgresql://postgres:password@localhost:5432/ai-chat_test (test-database.ts), which pnpm db:start provides. turbo.json passes TEST_DATABASE_URL through and never caches the test task.

Other fakes

createFakeSearchClient({ results, error }) stands in for Tavily and records every call. liveModelsFetch stands in for the OpenRouter and Ollama model lists. All live in packages/api/src/testing/.
