ai-chat architecture · Lesson 1

The package map

Seven packages, one rule: imports point down.

About 12 minutes · a browser · you'll write reaches(from, to), a cycle checker for import edges

Words you'll need

Package
One folder with its own package.json, such as packages/api. Other code imports it by name: @ai-chat/api.
Import edge
"A imports B": code in package A uses code from package B. The pictures show it as an arrow from A to B.
Cycle
A path of import edges that comes back to the package where it started.
Wiring
Code that only connects packages and passes objects in. It has no rules of its own.

1Seven packages, seven floors

Think of the app as a building where the stairs only go down. Each package is a floor, and code on one floor may use the floors below it, never the floors above.

Click @ai-chat/db in the picture: it has no red arrows, because the database package imports nothing. Then click apps/web: five red arrows, because the web app on the top floor joins everything. @ai-chat/ui sits to the side, because only the two top floors use it.

2What each floor owns

The split puts each kind of decision in one place. If a question is "is this allowed?", the answer lives in api. If it is "how does it look?", it lives in chat-react. Logic that the screen needs but that does not draw anything, such as which Message a new Branch continues, lives in chat-core, so a plain unit test can check it without React.

Quiz

You write code that decrypts a user's Provider credentials before a run. Which package owns it?

  1. @ai-chat/api
  2. @ai-chat/db
  3. @ai-chat/chat-core
  4. apps/web

3The web app only wires

Look at the two doors in the picture. /api/chat streams a reply, and /api/rpc answers every other call (list Conversations, switch Branch, stop a run). The route file for /api/chat is 16 lines long: it reads the session and calls handleChat(request, session, deps). services.ts builds deps once at start, and both doors share it.

The client side follows the same idea. chat-react never imports the router, so it asks the host app for links through a ChatAdapter. Follow one link to Key settings:

  1. chat-react renders <Link page={{ to: "keys" }}>.
  2. Link is ChatLink, which WebChatProvider in apps/web gave it.
  3. routeOf({ to: "keys" }) returns { to: "/settings/keys" }, so the router goes there.
Quiz

The URL of the Key settings page changes to /account/keys. Which package must change?

  1. @ai-chat/chat-react
  2. apps/web
  3. @ai-chat/chat-core
  4. @ai-chat/api

4Imports point down: no cycles

The ruleA new import edge from A to B is safe only if B can't already reach A.

A cycle is not only untidy. chat-core's type check runs tsc -b ../api first, because it needs api's types. If api also needed chat-core, neither could go first. Here is the check on a real mistake:

  1. A PR adds import { branchFrom } from "@ai-chat/chat-core/chat" to a file in api.
  2. chat-core already imports api, so chat-core reaches api.
  3. The new edge api → chat-core makes the loop api → chat-core → api. Refuse it, and move the shared function down into api.
Quiz

A PR adds an import from @ai-chat/db to @ai-chat/auth. What is wrong?

  1. Nothing is wrong with it.
  2. db may only import ui.
  3. It makes an import cycle.
  4. It skips the api floor.

Try it

Key takeaways

If you remember only one thing: imports point down. db stores, api decides, chat-react draws, and apps/web wires.

  • Seven floors. From the bottom: db, auth, api, chat-core, chat-react, apps/web, with ui to the side.
  • The web app only wires. Its routes hand requests to api with deps, and its ChatAdapter gives chat-react links.
  • Check before you import. An edge from A to B is safe only if B can't already reach A.

Go deeper: sources, side notes and a challenge

Why tools care about cycles

Turborepo, which runs this repo's tasks, models the packages as a graph with no loops:

"Turborepo uses a data structure called a directed acyclic graph (DAG) to understand your repository and its tasks." (Turborepo: Package and Task Graph)

The packages link to each other with pnpm's "workspace:*" versions, so an import of @ai-chat/api resolves to the local folder. See pnpm: Workspaces.

The browser imports a few api files

Most of what chat-core and chat-react take from api is import type, such as ChatCommand, so client and server agree on shapes and nothing runs. A few imports are real code: numberSources (api/src/chat/sources.ts), findModel (api/src/chat/models.ts) and providers (api/src/credentials/services.ts). Those files go into the browser bundle, so they must stay pure: today they import only zod or types. When you review a PR, check that such a file doesn't start to import @ai-chat/db or node:crypto.
