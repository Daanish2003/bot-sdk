The Message tree

Each Message points at its parent, and the Conversation points at one leaf.

About 12 minutes · a browser · you'll write pathTo(nodes, leafId), the function that finds the Active Branch

Words you'll need

Root
A Message with no parent (parentId is null). A Conversation can have more than one.
Leaf
A Message with no children: the end of a Branch.
Branch
One path through the tree, from a root down to a leaf (from CONTEXT.md).
Active Branch
The one Branch that the screen shows and that the next Message continues.

1A family tree, not a list

Think of a family tree where each person writes down only one thing: who their parent is. The picture is the test tree from branches.test.ts. Blue boxes are user Messages, grey boxes are replies, and m5 means "created at minute 5".

A list can't hold this, because a1 has two children. That is why the app doesn't use TanStack AI's ready-made storage: it keeps one straight transcript and deletes the later Messages when you edit or regenerate, so old Branches would be lost (ADR 0001).

2Two columns hold the whole tree

Look at schema/chat.ts: those two columns are the whole tree. To find children, the code loads every Message of the Conversation and groups them by parentId.

A Message that has ended never changes. An edit doesn't update the old row: it inserts a new sibling beside it (Lesson 6). Only a reply that is still streaming gets its parts written again, by its run.

3Walk up from the leaf

To show the Active Branch, pathTo in branches.ts starts at the leaf and follows parentId up, then turns the list around so the oldest Message comes first:

  1. Start at a2b, then its parent q2b, then a1, then q1.
  2. q1.parentId is null, so stop: [a2b, q2b, a1, q1].
  3. Reverse it: [q1, a1, q2b, a2b]. That is what the screen shows.

Two callers in store.ts use it. loadActiveBranch walks up from activeLeafId for conversation.get. loadPath walks up from the new Message's parent, so handleChat rebuilds the history for the Model from the database.

Key takeaways

If you remember only one thing: each Message stores only its parent, and the Active Branch is the walk up from activeLeafId, reversed.

  • A tree, not a list. Edits and regenerates add siblings, so old Branches stay. TanStack's linear storage would delete them (ADR 0001).
  • Two columns. message.parentId points up; conversation.activeLeafId picks the leaf.
  • Ended Messages never change. New Messages are inserted; old rows stay as they were.

Go deeper: sources, side notes and a challenge

The decision

"TanStack AI's persistence (@tanstack/ai-persistence withPersistence) keeps one linear transcript per thread and deletes later Messages on edit or regenerate, which rules out Branches." (ADR 0001)

The same ADR stores parts in the app's own versioned shape, not TanStack's UIMessage. That is Lesson 8.

Why "never mutated" matters

Because ended Messages never change, the path from a root to a given leaf is fixed. A Shared link can therefore store only a leaf id, not a copy of the Messages (ADR 0004, Lesson 12).

Side notes

  • loadActiveBranch loads every Message of the Conversation in one query and walks in memory. The index message_conversation_id_parent_id_idx keeps that query fast.
  • If the leaf id isn't in the Conversation, pathTo returns []. handleChat uses that to refuse a parentId from another Conversation: "The parent Message is not in this Conversation".
  • Deleting a Message would cascade to its children (onDelete: "cascade" on parentId), and activeLeafId becomes null ("set null"). Today only whole Conversations are deleted.
