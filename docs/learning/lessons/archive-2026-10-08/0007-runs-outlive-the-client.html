Runs outlive the client

Closing the tab stops reading. Only Stop stops the run.

Words you'll need

Disconnect
The browser stops reading the SSE stream: a reload, a closed tab, a lost network.
Poll
Ask the server for the same data again on a timer.
Run registry
deps.runs: a Map from a streaming Message's id to its run's AbortController, in one server process.
Sweep
A clean-up at server start that ends every Message row that a restart left streaming.

1A reload finds the run still going

Think of a radio station: switching off your radio doesn't stop the show. In the picture, the tab closes in the middle of a reply, and the run keeps going to complete (Lesson 4).

When the page loads again, ChatView sees a Message with status: "streaming" that it didn't send. So it sets polling and refetches conversation.get every 1,000 ms. Each answer shows the latest snapshot, so the text grows in jumps, not word by word. When no Message is streaming, the polling stops and the Conversation panel refreshes.

2Stop is a call, not a disconnect

A disconnect can't mean Stop, because a reload is also a disconnect. So Stop is its own oRPC call, and the server alone decides how the run ends. Follow one Stop:

  1. stop() in ChatView refetches conversation.get, because useChat knows only its own id for the reply, not the server's.
  2. It finds the streaming Message and calls chat.stop({ messageId }). findMessage checks that the user owns it.
  3. stopRun looks in deps.runs. If the run is there, it calls abort(), and the run saves itself stopped. If not, it sets the row to stopped, but only where the status is still streaming.
Quiz

A user calls chat.stop on a reply that ended complete a minute ago. What happens?

  1. Nothing changes; it stays complete.
  2. The row changes to stopped.
  3. The server answers NOT_FOUND.
  4. The server starts it again.

3Three guards for runs nobody watches

A run with no reader needs limits, because nobody is there to give up on it.

untilAborted races each iterator.next() against the abort signal. Some adapters ignore the signal (Ollama's), so the loop stops reading at once and leaves their stream behind. The cap (runCapMs, 5 minutes) aborts a run that takes too long, which saves "timed out". A restart kills every run in memory, so at boot a Nitro plugin calls sweepInterruptedRuns: each streaming row created before boot becomes error "interrupted", and its running searches become cancelled.

4The limit: one process

deps.runs is a plain Map in one process. That is fine for one process under Docker Compose, as ADR 0002 says. Look at what two processes would break:

  1. The run lives in process A. Stop arrives at process B, whose deps.runs has no entry, so B sets the row stopped.
  2. The run in A never sees an abort. Its snapshots write only parts, so the text keeps growing under a stopped badge.
  3. A's finally writes status: "complete" without a condition, so the Stop is lost. A restart of B would also sweep A's live runs as "interrupted".

Key takeaways

If you remember only one thing: a disconnect only stops reading; the server alone decides how a run ends.

  • Reload, then poll. A page that finds a streaming Message refetches conversation.get every second until none is left.
  • Stop is chat.stop. It aborts the run through deps.runs, or marks a leftover streaming row stopped.
  • Guards, and one process. untilAborted, a 5-minute cap and a boot sweep keep unwatched runs finite; the registry works only in one process.

Go deeper: sources, side notes and a challenge

What the ADR gave up

"Resumable streams (re-attach to live tokens): best UX, but needs TanStack AI's durable-stream plumbing, which we gave up by not using withPersistence (ADR 0001)." (ADR 0002)

That is why a reloaded page polls snapshots instead of re-attaching to the live stream.

The tests

The chat.stop block in handle-chat.integration.test.ts covers each path: "stops reading an adapter that ignores the abort signal" (a deafAdapter), "marks a streaming Message with no run in this process stopped", and "leaves a Message that already ended alone".

Where the code lives

stopRun, untilAborted and sweepInterruptedRuns are in run.ts. The boot hook is apps/web/server/plugins/sweep-interrupted-runs.ts. Polling and stop() are in chat-view.tsx. The race uses Promise.race and AbortController.
