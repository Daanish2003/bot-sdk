Automatic titles

After a reply completes, the server names the Conversation, and the top bar waits for it.

About 12 minutes · a browser · you'll write fallbackTitle(first) and awaitingTitle(conversation)

Words you'll need

Title Model
The Model that writes titles. The user picks it in Keys & settings; the default is "Same as first reply".
Fire-and-forget
Start an async call without waiting for it. Nothing waits, so it must catch its own errors.
Fallback title
The first words of the first Message, used when no Model can write a title.
Polling
Asking the server again on a timer, here once a second, until the answer changes.

Warm-up · Lesson 4

Where does a run decide its final status: complete, stopped or error?

  1. In the finally block.
  2. In the client's useChat.
  3. Inside handleChat's send transaction.
  4. In the boot sweep.

1When: after a complete run

Look at the end of the run in the picture. The finally block in startRun saves the status and closes the stream. Then, only if the run ended complete, it calls void titleConversation(deps, messageId). The void means fire-and-forget: nothing waits, and titleConversation catches every error itself.

The first thing titleConversation checks is the title. If the Conversation already has one, it stops. So the first complete reply titles a Conversation, even if earlier replies failed.

Quiz

The first reply ends in error. The user regenerates, and the second reply completes. When is the Conversation titled?

  1. After the first reply.
  2. After the second reply.
  3. Never, it stays Untitled.
  4. Only after a rename.

2Which Model writes it

Follow the ladder in the picture from the top:

  1. The Model is user_settings.titleModel, or, when that is null, the Model that wrote this reply.
  2. findModel looks it up in the curated list, and loadCredentials gets the user's key for its Provider (Lesson 9).
  3. chat({ stream: false }) gets the first user Message and the reply, each cut to 2,000 characters, with the prompt "Write a short title (at most 6 words)".
  4. cleanTitle makes it one line with no quotes or end period, at most 100 characters.

3The fallback title

If there is no Model, no key, or the call fails, the title is the start of the first Message. fallbackTitle joins all whitespace into single spaces. If the result is 50 characters or fewer, that is the title. If not, it cuts at 50 and moves back to the last space, but only when that space is after character 25. Then it adds "…".

4How the top bar finds out

The browser doesn't get a message when the title is written. So ConversationTitle in top-bar.tsx polls conversation.get while awaitingTitle is true: there is no title, nothing is streaming, and an assistant Message is complete. It stops when the title arrives, or after titleWaitMs (30 seconds). Then it refreshes the Conversation panel, so the new name shows there too.

A manual rename always wins, because the server writes the title with where title is null.

Quiz

A user renames the Conversation while the title call is still running. Which title stays?

  1. The user's manual rename.
  2. The generated automatic title.
  3. Whichever finished writing last.
  4. The fallback first words.

Key takeaways

If you remember only one thing: a complete run fires titleConversation and forgets it; the top bar polls until the title appears.

  • Only while untitled. It runs after any complete run, but writes only where title is null, so a rename wins.
  • Title Model, else the reply's Model. No Model, no key or a failed call gives the fallback title.
  • The client polls. awaitingTitle → refetch every 1 s, for at most 30 s.

Go deeper: sources, side notes and a challenge

A live-listed Model gets the fallback

findModel searches only curatedModels. A reply from a Model that the picker lists live (OpenRouter's or Ollama's lists) isn't there, so with the default "Same as first reply" setting, generateTitle returns "" and the fallback title is used. Picking a curated Title Model in Keys & settings fixes that. Check it yourself in title.ts and models.ts.

Why credentials must be on the server

The title is made after the run, with nobody connected. That is one of the two reasons ADR 0003 gives for keeping Provider credentials on the server (Lesson 9).

Polling in TanStack Query

refetchInterval can be a function of the query, which returns a delay or false. That is how the top bar turns polling on and off. See TanStack Query: useQuery.
