Web search and Sources

A search is one part of a reply. A failure is only its state.

About 14 minutes · a browser · you'll write numberSources(searches), which numbers a reply's Sources

Words you'll need

Tool
A function the Model can ask the server to run in the middle of a reply. Here there is one: web_search.
Tool credential
A user's own API key for a service a tool needs. For web search, it is a Tavily key.
Source
A web page that a search returned during an assistant Message, numbered within that Message.
Citation
The chip in the reply's text that points at a Source. A Source is the page; a citation is the pointer.

1Three gates before a search

Think of a door with three locks. handleChat offers the tool only when the command asks for search (webSearch: true), the Model has tools (model.tools) and the user has a Tavily Tool credential. If one lock stays closed, the run gets no tool and the Model can't search.

The client shows the same locks before you send: searchToggle in chat-core greys out the Search toggle and says why, such as "This Model can't use tools, so it can't search the web". The server still checks again, because the client can be wrong.

2A search sits between the text

A reply is a list of parts (Lesson 8). When the Model calls the tool, createWebSearchTool calls parts.startSearch, which pushes a web_search part with state: "running". When Tavily answers, finishSearch sets it to done with up to 5 results. Text that streams after that starts a new text part, so the order on screen is the order of events.

One reply may search at most 3 times (maxSearchesPerReply). A fourth call gets the result "search limit reached" and searches nothing.

3A failure is a state, not an error

When a search fails, the tool doesn't throw. It sets the part to error with a reason and gives the Model a short result such as { error: "Tavily rejected the API key" }. The Model reads that and can still answer. Only an abort is different: the run's finally calls cancelRunningSearches, so a search that never finished is saved as cancelled.

Quiz

Tavily answers HTTP 432 during a reply, and the Model then finishes its answer. How is the Message saved?

  1. complete, and the search shows error
  2. error, and the reply stops there
  3. stopped, and the search is cancelled
  4. streaming, until Tavily answers again later

4Sources get numbers; links become citations

Sources are never stored. The renderer computes them from the parts with numberSources: it walks every result of every search in order and gives each new page the next number. Two URLs are the same page when their sourceKey matches, which is the URL without its #fragment and trailing slash.

The Model cites with ordinary markdown links, because citationPrompt asks it to. Then citationFor(href, sources) checks each link: if its key matches a Source, the link shows as that Source's numbered chip. Any other link stays a plain link.

Key takeaways

If you remember only one thing: a search is a part of the reply, its failure is a state of that part, and Sources are computed from the parts, never stored.

  • Three gates. Search asked for, a Model with tools, and a Tavily Tool credential. The server checks all three.
  • Failures stay small. A failed search is error on its part; the Message still ends complete.
  • Number by first appearance. numberSources dedupes by sourceKey; citationFor turns a matching link into a chip.

Go deeper: sources, side notes and a challenge

Read the code

  • web-search-tool.ts: the server tool, the limit and the catch.
  • tavily.ts: the HTTP status to reason map and the 15-second timeout.
  • sources.ts and citations.ts: browser-safe, so chat-react imports them (Lesson 1's side note).
  • chat-core/web-search.ts: searchToggle and the search row's one-line text.

History without the tool

When the next request does not offer the tool (Search off, or a Model without tools), toModelMessages replays an old search as text, such as [Searched the web for "x": …]. With the tool, it replays as a real tool call and result. Stored history is never rewritten (parts.ts).

Why not [1] markers?

citationPrompt tells the Model: "Don't add numbered markers like [1] or a list of sources at the end; the app shows the sources." Links to exact URLs can be checked against the results; a bare number can't.
