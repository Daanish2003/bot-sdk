What wakes the agent

Only you woke the Bot in Lesson 12. Now a Routine, a Check-in or a webhook can wake it too, and each wake says where it came from.

About 14 minutes · a browser · no code to write; you'll answer the quizzes and follow the Routine states

Words you'll need

Routine
A prompt that runs on a schedule, or whenever its webhook URL is called.
Approval
The user's OK. A new or changed Routine does nothing until you give it.
Check-in
One moment the Bot sets for itself, with a note to its future self.
Wake notice
The first lines of a Trigger's text. They say what woke the Bot.

Warm-up · Lesson 12

A Turn is running when two Routine runs come due. Where do they wait?

  1. They start a second Turn at once
  2. They are dropped
  3. They wait in the Conversation queue, and the next Turn takes both

1A Routine waits for your OK

The Bot saves a Routine with create_routine, and it starts as pending. The app shows an inline card after that Turn, with Approve and Decline. Slide 29 gives the one rule that ships in this step: new Routines need your OK. Approving queues the first run for the next slot, and it never wakes the Bot by itself.

Any change to an approved Routine, active or paused, sends it back for your OK. An active one stops at once. delete_routine needs no OK. You can pause and resume a Routine, and a resume needs no new OK. The Bot's list of Routines in its system prompt shows (waiting for OK) on a pending one.

2Each run queues the next

A schedule is days and a time, like weekdays at 08:00 in your zone. The run for one slot queues the run for the next slot in the same transaction. It then hands the Router a Trigger with source routine, channel schedule and the ID routine:<id>:<slot>. The chain never has two runs for one slot.

A run that comes late still runs once. The next slot is counted from now, so missed slots are not run again. The Trigger's text starts with a wake notice: Routine "morning-brief" ran at Mon 2026-10-19 08:00 (Europe/London). The user didn't send this; it's their approved Routine. If there's nothing worth telling the user, send nothing. Then comes the prompt as it was at the run. A run with the Quota spent hands no Trigger, but the chain still goes on.

3A webhook is a secret URL

A webhook Routine has no schedule. Its URL holds a random token. The URL is shown once, at the first approval, and only the token's hash is stored. If you rotate the URL, the old one answers 404 from then on. A token that matches no active Routine (pending and paused ones too) also gets 404, so the URL reveals nothing. The Model never sees the token.

A call with a known token gets 202 straight away. A repeat with the same Idempotency-Key makes no second Trigger. A body over 64 KB gets 413, and an Idempotency-Key over 255 characters gets 400. The body is wrapped in a block labelled untrusted data, not instructions. Anyone with the URL can wake the Routine, so the Turn must not obey text from a webhook (slide 29).

4A Check-in needs no OK

The Bot sets a Check-in with set_check_in. It must be at least a minute ahead. It fires once, as source check_in, and its wake notice gives the time it was set and the note. A Check-in fires even when the Quota is spent, and it is marked as fired so it never waits as pending. Use list_check_ins to see them, and cancel_check_in to stop one. Anything that repeats is a Routine instead.

Key takeaways

If you remember only one thing: every wake is a Trigger, and every Trigger says where it came from: you, a Routine (schedule or webhook) or a Check-in.

  • A new Routine waits for your OK. An edit sends it back. Approval queues the first run for the next slot.
  • Each run queues the next. A missed slot runs once, late, and the chain goes on from now.
  • A webhook is a secret URL. Only its hash is stored, and its body is untrusted data.

Go deeper: sources, side notes and a challenge

The lecture

  • Slide 11 (routines/): a Routine is a prompt plus a time, such as weekdays at 8:00.
  • Slide 14, "What wakes the agent": a Routine runs "on a schedule or webhook", and the question "Anything worth saying?" decides whether the run sends a Message.
  • Slide 29, "New routines need your OK": the one safety rule that ships in this step. The webhook body is untrusted data, and the full set of safety rules is step 9.

Side notes

  • Routines are one row in chat.bot_routine with a schedule and a zone each. They fire through a self-chaining job, not a cron table (#537, and the ADR 0011 amendment). The runner has no cron, so each run queues the next one (#536).
  • A run takes the Bot's one Conversation queue, with no batching of its own (#539). Pausing or deleting a Routine drops the Triggers no Turn has taken yet.
  • The webhook design is in ADR 0021 (#541). The token is 256 random bits, stored as a SHA-256 hash. The URL is shown once, and the user can rotate it. The batch rule of Lesson 12 is what keeps a flood of calls to few Turns.
  • Check-ins are kept apart from Routines and are never gated by an OK (#540). The web app draws them as inline lines.
  • The app's Routines and Check-ins UI is variant A of #542: the approval card and the run dividers sit in the thread, and the webhook URL has Copy and Rotate.
  • Tests: bot-routine.integration.test.ts, bot-routine-fire.integration.test.ts, bot-routine-webhook.integration.test.ts and bot-check-in.integration.test.ts. Evals: eval/turn/routine-cases.ts.
