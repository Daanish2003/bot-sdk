The Host and the SDK

The chat feature is one copied folder in four parts, and apps/web is just one Host.

About 12 minutes · a browser · you'll write allowed(from, to, typeOnly), the import rule a reviewer checks

Words you'll need

Chat SDK
The reusable chat feature in packages/chat-sdk. It knows users only by id.
Host
An app that embeds the Chat SDK and gives it users, routes and Postgres.
core/
The SDK code a Host never edits: shared, server, client.
ui/
The SDK's React components, which the Host owns and may change.

1Floors of a building

Think of the SDK as a building with floors, and its imports as stairs that only go down. ui is the top floor, client and server sit side by side, and shared is the ground. shared imports only npm packages, such as zod and @tanstack/ai.

The Host stands outside the dashed frame. It imports the SDK, but no file inside the frame imports the Host or any @ai-chat/* package. The chat tables also live inside: chat-schema.ts puts them in their own Postgres schema, chat. @ai-chat/db holds only the Host's tables.

2Copied, not installed

The SDK is never published to npm. A Host runs pnpm -F @ai-chat/chat-sdk copy <dest> (scripts/copy.ts). Because core/ is replaced every time, an edit there is lost on the next update. ui/ is copied only when the Host has none yet, so the Host can restyle it freely (ADR 0005).

Quiz

A Host finds a bug in core/server/chat/run.ts in its copy. Where does the fix go?

  1. In the Host's copied core.
  2. In the Host's own ui folder.
  3. In packages/chat-sdk, then copy.
  4. In the apps/web route file.

3What the Host gives

The SDK can't assume the Host's stack, so the Host gives it three things. In services.ts, apps/web passes databaseUrl (Postgres) and getUser, which asks Better Auth for the session and returns { id } or null. The third is one catch-all route, routes/api/chat/$.ts, which passes every method to chat.handler(request).

Look at the picture: the handler, not the Host, decides what a path means. It sends /api/chat/rpc/* to the oRPC routers and POST /api/chat/run to handleChat (create-chat.ts). Lesson 2 opens createChat itself.

4Stairs go down; types may look up

There is one exception to "only down". client and ui import the type of the server's router, so their calls are type-checked: import type { AppRouterClient } from "../server/routers/index" in chat-client.ts. TypeScript erases import type lines, so no server code reaches the browser.

The ruleAn import is allowed when it goes down the map. client or ui may reach up to server only with import type. Nothing imports the Host.
Quiz

A PR adds import { startRun } from "../server/chat/run" to a file in core/client. What do you say?

  1. Refuse: it ships server code.
  2. Accept: types are always erased.
  3. Accept: move it into ui first.
  4. Refuse: move it to shared.

Key takeaways

If you remember only one thing: the chat feature lives in packages/chat-sdk; the Host only gives it users, a route and Postgres.

  • Four floors. ui → client → shared, and server → shared. Stairs go down.
  • Copied, not installed. core/ is replaced on each copy; ui/ is the Host's to change.
  • Types may look up. client and ui reach server only with import type, and nothing imports the Host.

Go deeper: sources, side notes and a challenge

The decision

"It is copied, never published: the canonical source is one workspace package, packages/chat-sdk/, laid out exactly as a Host receives it, and apps/web is just one Host, importing only its public entry points." (ADR 0005)

The ADR also lists what was rejected: publishing npm packages, assuming this repo's stack, letting the Host edit everything, and shipping copies of the shadcn primitives.

Side notes

  • ui/ reaches buttons and dialogs through the Host's own @/components/ui/* alias. In this repo, apps/web/tsconfig.json points that alias at packages/ui, so it is drawn as an edge to @ai-chat/ui.
  • The copy script never copies tests (test, eval, *.test.*), and it also copies extras/ only once, like ui/. core/VERSION records the commit that was copied.
  • packages/chat-sdk/package.json lists @ai-chat/db, but only the tests and the memory eval import it. core/ imports no @ai-chat/* package.
  • ADR 0005 says "the client never imports the server". The code does reach the server with import type (in chat-client.ts, search.ts and three ui/ files), which keeps the spirit: no server code is bundled.
