The week-one loop, and talking only through a tool

A Bot's model text stays private. The user reads only what the Bot sends with one tool.

About 12 minutes · a browser · you'll write playTurn(steps), the function that decides which Messages a Turn sends

Words you'll need

Turn
One Bot working on what a user Message started, until it stops.
Step
One call to the Model. It answers with plain text, tool calls, or both.
SendToUser
The Bot's only tool. Each call sends the user one Message.
Transcript
The Model's private side of a Turn. It is saved, and it is never a Message.

1A Turn is a loop of Steps

This is slide 2's week-one loop, made safe to ship. A user Message starts a Turn. The Turn calls the Model, runs the tools the Model asked for, and calls the Model again. It repeats until the Model stops. The Host's request runs the whole Turn.

runTurn calls TanStack AI's chat() with one tool and a small middleware. A runaway Model cannot loop for ever: a Turn gets 10 Steps (turnStepLimit) and 5 minutes (turnTimeLimitMs). Past either limit it ends error, and the Messages already sent stay.

2The user reads only what SendToUser sends

Think of a person who thinks out loud in a locked room and passes notes under the door. The user sees the notes. The Model's own text is never shown. The fixed botSystemPrompt tells the Model so.

send_to_user takes { text, endTurn }, and both are required. Each call appends one Message to the Conversation straight away. If text is empty, the tool sends nothing and returns emptyTextError, which tells the Model what to do next.

When the Turn ends, however it ends, runTurn writes the transcript to the bot_turn row. The next Turn replays it as input (modelInput). So the Model remembers what it thought and what it chose not to say. The Model also sees its own sends as send_to_user calls, never as plain text.

Quiz

In a Step, the Model writes "Sure, checking now" as plain text and calls no tool. What does the user see?

  1. A Message with that text
  2. A "Couldn't reply" note
  3. Nothing. The text goes into the private transcript.

3Quiet is allowed, and the last send can end the Turn

After each Step the middleware's onShouldContinue decides what happens next. A Step with no tool call ends the Turn, quiet. The user sees "Seen ✓" under their last Message and nothing else. A Step where a send had endTurn: true ends the Turn with no further Model call. This is slide 22's "one less step", and a normal reply costs one Step.

There is no NO_REPLY token and no forced tool_choice. Quiet is a reply with no text and no tool call.

Amended by #531. A Model sometimes writes a refusal or a question as plain text, which the user never sees. So a Step that ends in plain text and no tool call gets one more Step, once per Turn, after a short note: that text was not delivered, so send it with send_to_user if the user needs it, or reply with no text. If that Step is plain text again, the Turn ends quiet and complete. The extra Step counts toward the 10-Step limit; with no Step left, there is no note, and the Turn ends quiet. The note stays in the transcript.

4bot.send streams each Message

bot.send is an oRPC streaming procedure. It yields { type: "message" } first for the saved user Message, then once for each send, and last { type: "turnEnded", status }. So "On it…" shows before a slower answer. A refusal (402 Quota, 409 a Turn is running) is thrown before the stream starts, so the user's Message is not saved.

Key takeaways

If you remember only one thing: a Bot reaches the user only by calling send_to_user, and everything else it writes stays in a private transcript.

  • A Turn is a loop of Steps. It ends on a Step with no tool call, on an endTurn: true send, or at a limit.
  • Quiet is a normal ending. The user sees "Seen ✓", and the Model still remembers the Turn.
  • Each send is a Message at once. bot.send streams it to the browser as it is appended.

Go deeper: sources, side notes and a challenge

The lecture

  • Slide 2: the week-one loop. Slide 3: an always-on agent "only messages you when it calls a send tool, so it can stay quiet". Slide 8: the Bot app, a sidebar of Bots with previews. Slide 22, "One tool for talking to you": thinking stays private, quiet is allowed, and "one less step". Its fourth card is partly hidden, so "one less step" is read as ending the Turn on the last message.
  • Slide 22's "rich messages" are not built. send_to_user is text only (step 12).

Side notes

  • The note after a plain-text Step is a recorded deviation: the lecture is silent here. Its reason is the Turn eval's numbers, kept next to undeliveredTextReminder in turn.ts. After a crash it is rebuilt from the recorded model call, so it needs no Checkpoint.
  • sendToBot checks, in order: the Bot, the Model, then Quota (meter.mayRun()). Then one transaction locks the Conversation, refuses with 409 if a fresh Turn is running, marks a stale one error with interrupted, and saves the user Message and the Turn row.
  • The client holds the in-flight send in a store outside the view (useBotTurn), so opening another Bot does not stop a Turn. Closing the tab aborts the request signal, and the Turn ends stopped.
  • "Seen ✓" is derived: the latest Turn ended complete and the last Message is the user's.

What step 2 changes

Today the Turn lives inside one request, and its transcript is written once, at the end. Step 2 makes the Turn survive a crash and saves each Step as it happens, and it pulls the loop out into a runner plugin (spec #463, out of scope).
