The Bot SDK, its core and its plugins

One core holds the shared base. Each feature is a plugin, a plain object that sits on it.

1One core, rooms added by the Host

Think of the Bot SDK as a house. The core is the foundation: the database, the blob store, pub/sub, logging, and the Conversation with its Messages and attachments. Every Host gets it. The plugins are rooms the Host adds: models (keys, quota and usage) and assistant (Runs, tools, Memory and more).

A plugin calls another plugin only when it lists that plugin in requires, as assistant lists models. The core imports plugin code in one place only, the schema module that composes the tables. Everywhere else it uses import type.

A Host copies the folder with pnpm -F @ai-chat/bot-sdk copy <dest>. Each copy replaces core/ and every plugin folder, but not a plugin's ui/. The root ui/ and extras/ are copied only when missing, and tests are never copied (scripts/copy.ts).

2A plugin is a plain object

A plugin is the BotSdkPlugin type in core/server/plugin.ts. The shape of assistant, trimmed, looks like this: 

{
  id: "assistant",
  requires: ["models"],
  router: appRouter,
  init: (sdk) => { …; return { api }; },
  start: (sdk) => lifecycleOf(sdk).start(),
  stop: (sdk) => lifecycleOf(sdk).stop(),
  deleteUser: assistantUserDelete,
}

Each hook gets a BotSdkContext: the database, the keyring, the event hooks, a guarded fetch and plugin(id). Reading sdk.plugin("models").quota(userId) is typed, because models adds its API to PluginApis by declaration merging. It throws when models is not enabled.

3One schema, composed from parts

A plugin's schema module is plain Drizzle. It exports its own tables and enums, plus, for each core table, the columns and indexes it adds. The assistant adds model, reasoning_effort, project_id, tool_settings and temporary to conversation, in the same column builders the core uses.

core/server/db/schema.ts joins the parts into one conversation and one message. If two parts declare the same table, enum, column or index, the module throws at load and names both. CI runs drizzle-kit generate and fails if the migrations folder changes.

4Every delete goes through one door

Five paths delete Conversations: a single delete, delete all, the Temporary sweep, a Project delete and the user delete. Each one calls deleteConversations before it removes any parent row. It selects the ids, runs each plugin's before in the transaction, deletes the rows, and then runs each after once the commit is done.

A before that throws rolls the delete back. An after that throws is logged, and the other hooks still run. The assistant's before stops the Runs in the deleted Conversations, and its after deletes their Generated image bytes.

Key takeaways

If you remember only one thing: the Bot SDK is one core, and every feature is a plugin on it. The shared paths take each plugin's part through one door.

  • The core is the foundation. Plugins call each other only through requires and plugin(id).
  • A plugin is a plain object. init, start and stop run in dependency order, and stop runs in reverse.
  • One door for each shared path. One composed schema, and one deleteConversations that every delete calls.

Go deeper: sources, side notes and a challenge

The decision

"Everything else is a plugin: models, runner, assistant (today's chat), bot (…), memory, knowledge, computer and channels. A plugin declares requires, and the core throws at startup when one is missing." (ADR 0020, amended for the field DSL)

The ADR also says the core holds the Conversation, because it is to this SDK what user is to Better Auth. Plugin export paths end in /server, /client or /ui.

Side notes

  • Construction checks the plugins in orderPlugins. It throws on a duplicate id, a missing requirement or a cycle. mergeRouters throws when two plugins claim one router key.
  • start() checks that the schema is migrated before any plugin starts. stop() sets stopping, then stops the plugins in reverse, then closes the runtime.
  • deleteUser runs each plugin's before in reverse dependency order, then the core's own delete step. The export merge throws when two plugins give one key.
  • The models schema has fields: {} by type. Giving models a column means spreading its fields in schema.ts, which is an edit to the core.
  • Two owner calls are still open. The conversation router stays in the assistant, because its reads filter on assistant fields, and user_settings belongs to the assistant.
