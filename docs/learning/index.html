Own the Chat SDK

20 short lessons, from the core and its plugins to the test seams.

10–15 minutes each · take them in order · grey lessons come in the next batch · ask your teacher (Claude) about anything unclear

Part 1 · The Bot SDK

  1. The Bot SDK, its core and its pluginsOne core, plugins as plain objects, one composed schema and one delete path.
  2. The week-one loop, and talking only through a toolA Turn is Steps; the user reads only what send_to_user sends.
  3. Durable workflows, saving each stepA Turn is a job that saves a Checkpoint per piece of work and replays after a crash.
  4. One turn at a time per ConversationThe Router drops repeats, quick Messages batch, and you skip the line.
  5. The agent’s computer and its lifecycleA sandbox that pauses, files synced to the server, and a sleep check that never fires mid-Turn.
  6. What wakes the agentA Routine waits for your OK, each run queues the next, and a webhook is a secret URL.
  7. One main agent, many HelpersThe Bot hands a task to a Helper, hears back as a Trigger, and hands you the Screen at a login.
  8. How the agent remembersPlain files on the Computer, a ranked Log in each prompt, and a pass that only removes lines it was shown.
  9. Keeping the start of the prompt the sameA stored Prompt start, Change notes in the newest message, and a cache chip that flags a bug miss.
  10. How we keep it safeA second model checks risky calls, only your words count as permission, and a Secret never reaches the model.
  11. Knowledge kept in filesA Skill is a plain file with a one-line pointer, and a Bot can learn one by watching you.
  12. Knowledge written downA user's documents are plain files every Bot reads, with no index, and what the reworded-question eval showed.
  13. Thin client, thick server, and syncThe server numbers each change, and a tab asks for what came after its number (ADR 0026).
